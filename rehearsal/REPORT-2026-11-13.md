## 2. 發現的問題與修正

| # | 問題 | 修正 | commit |
|---|---|---|---|
| 1 | setup.sh 只把 PATH／LANG／TZ 寫進 `~/.bashrc`。Ubuntu 的 `.bashrc` 遇到非互動 shell 會直接 return，所以 root 跑 `bash -lc 'claude'` 時找不到 claude，`ssh 主機 '…'` 也一樣 | 同時寫入登入設定檔（`~/.bash_profile` → `~/.bash_login` → `~/.profile`，取第一個存在的）；PATH 那一行先檢查再加，避免重複 | `96b43ed` |
| 2 | `exec bash -l` 和下一行一起貼上時，`exec` 換掉 shell 後第二行被 readline 的緩衝吃掉，claude 沒有啟動。使用者連踩兩次 | 改成一行 `source ~/.bashrc; cd ~/Elephant && claude`（README、setup.sh 的「下一步」、HANDOFF） | `e063f8b` |
| 3 | Claude 建了 `work/inspect.py`，蓋掉 Python 內建的 inspect，導致 pandas 匯入失敗；想改名或刪除又被擋，最後只能請使用者手動 rm | CLAUDE.md 加檔名規則；白名單加 `Bash(mv work/*)`、`Bash(rm work/*)`、`Bash(rm -f work/*)`。實測 `:*` 前綴寫法蓋不過內建的「工作目錄內檔案操作要核准」，萬用字元寫法才有效 | `e063f8b` |
| 4 | `sed -n '1p;$p'` 和 `od` 被擋 | 白名單加 `Bash(sed -n:*)`、`Bash(od:*)` | `e063f8b` |
| 5 | duckdb 2.0 拿掉了 relation 的 `.fetchone()`；讀 `\x01` 檔試錯了 3 次 | `docs/hdfs.md` 補上實測可用的寫法 | `e063f8b` |

修正後在新的容器 rh3 從頭重跑：開局被擋的次數從 5 次降到 1 次，輔助程式也照新規則取名為 `check_*.py`。

## 3. 還沒解決的風險

1. **deny 規則可以被繞過**。白名單有 `Bash(python3:*)`、`Bash(awk:*)`，所以 `python3 -c "subprocess.run(['hdfs','dfs','-rm',…])"`、`awk 'BEGIN{system(…)}'` 會被自動放行。目前的保護靠兩層：模型遵守 CLAUDE.md（這次測試有守住），以及現場 HDFS 本身的權限。
   - 比賽當天先用 `hdfs dfs -ls -d /資料路徑` 看擁有者。如果你的帳號就是擁有者或 superuser，代表 HDFS 那一層擋不住。
   - 要加強的話，可以加一個 PreToolUse hook，掃描 Bash 指令裡的 HDFS 寫入操作。但它擋不到寫進 `.py` 檔裡的程式碼。
2. **登入的前提沒有驗證過**：需要另一台有瀏覽器的裝置，而且現場網路要能連到 claude.ai。如果現場不准用手機或筆電、或者擋了 claude.ai，就沒辦法登入，目前也沒有備案（例如 API key）。
3. **這次沒有模擬到的情況**：
   - Kerberos
   - 沒有 sudo 的帳號
   - 網路受限，或只能用內部的 PyPI 鏡像
   - 真的 Hive metastore，需要用 beeline 查 schema
   - GB 級的大資料
   - ARM 架構的機器
4. **白名單管不到的內建檢查**：shell 重導向寫檔（`>`、`>>`）、含「大括號加引號」的 heredoc、含變數的 for 迴圈。在 `-p` 模式下這些會直接被拒絕，在互動模式下會跳出確認。這次 Claude 每次都在下一步就改用 Write 或寫成 .py 檔繞過去。要再省一點時間，可以在 CLAUDE.md 加一句「寫檔用 Write/Edit；長一點的 Python 寫成 work/*.py 再跑」（還沒改）。
5. **`python3 -I` 找不到 pandas**，因為套件裝在 user site。影響很小，Claude 會自己拿掉 `-I`。
6. **pip 一律裝最新版**：這次裝到的 duckdb 2.0 就改了 API。要不要限制大版本，例如 `duckdb<3`，由你決定。
7. **假資料的限制**：我產生的交易資料裡，碰巧有會員中途換等級，交易時間也平均分布在 24 小時。Claude 兩件事都抓到了，但這是假資料的副作用，不是刻意設計的陷阱。

## 4. 比賽當天流程的建議

- 照新版 README 走，一共 3 個指令：
  1. `sudo apt-get update && sudo apt-get install -y git`
  2. `git clone … && bash ~/Elephant/bootstrap.sh`
  3. `source ~/.bashrc; cd ~/Elephant && claude`
- 預估時間：
  - 從空機器到可以開始解題：約 3～5 分鐘（apt 的速度差很多，18～53 秒）
  - 開局：約 2 分鐘
  - 每題：約 30～60 秒
- 登入用的裝置（手機或筆電的瀏覽器）事先準備好。熟練之後登入只要 22 秒。
- 先決定 Q4 這類「比率平均」題要交哪個版本。Claude 會照字面選簡單平均當主答案，同時列出加權平均。`docs/pitfalls.md` 目前只寫「兩種都算」，沒有寫優先交哪一個。
- 可以再省的時間：setup 用 apt 裝 python3-pip 時，預設會一起裝 build-essential 等推薦套件，花了 28 秒。加 `--no-install-recommends` 大約能省 20 秒（還沒改，也還沒測）。
